一、真实前提（必须接受）

机械臂具备 ROS / ROS2 支持

灵巧手 仅提供官方 C++ SDK

动捕手套 仅提供官方 SDK

视觉系统通过 SDK 或独立进程提供数据

所有 非 ROS2 设备 必须通过 自定义 ROS2 Node 封装 SDK 的方式接入系统。

二、系统总体架构约束

ROS2 是系统的通信与流程中枢

所有设备对系统暴露的接口必须是 ROS2

SDK 只能存在于 ROS2 Node 内部

Qt 不允许直接调用任何设备 SDK

Qt 仅通过 ROS2 Topic / Service 与系统通信

Qt3D 仅用于状态可视化

只接收设备状态

不反向控制设备

三、设备接入规范（重点）

对于灵巧手、动捕手套等仅提供 SDK 的设备：

编写独立的 ROS2 Node（C++）

Node 内部：

初始化 SDK

管理设备连接状态

处理 SDK 回调或轮询

Node 对外：

发布设备状态 Topic

提供控制 Service / Action（如抓取、复位）

SDK 不允许暴露给 ROS2 以外的模块。

四、流程控制与安全机制

所有跨设备流程由 流程控制 ROS2 Node 实现

流程逻辑采用 有限状态机 FSM

任一设备状态异常：

流程立即暂停

禁止自动推进

五、权限与安全

Qt 侧进行用户权限校验

流程控制 Node 进行二次校验

所有控制行为必须可记录、可追溯

是否需要新增 ROS2 Node（SDK wrapper）

Node 内部如何调用 SDK

Node 对外提供的 ROS2 接口

异常与失控处理方式
